This comprehensive report evaluates three distinct implementation approaches for mobile UI automation: ViBR framework with OpenAI models, ViBR framework with Gemini 2.5, and src_LLM (direct Gemini 2.5 Pro implementation). Each approach was tested across two input quality levels: bad quality (handheld video) and good quality (server/programmatic), with detailed step-by-step workflows and success metrics.

Key Finding:
The src_LLM implementation with Gemini 2.5 Pro significantly outperforms the ViBR framework variants, achieving 60-100% completion rates across most applications. The gap is particularly pronounced in good quality input scenarios, suggesting that direct API integration is superior to framework abstraction for this use case.

Failure Modes Analysis

1. Framework-Level Failures (ViBR-Specific)

Affected Apps: AntennaPod, Luxalarm, Jigsaw, HomeMedKit

Root Cause: ViBR framework cannot interpret or execute commands for complex workflows. Even when the underlying Gemini 2.5 model is capable (as proven by src_LLM), ViBR's architecture fails.

Frequency: ~40% of ViBR test cases

2. Getting Stuck on Homescreen

Affected Apps: LuxAlarm, HomeMedKit (with ViBR)

Root Cause: Unable to identify the primary action button ("+", "Add"). ViBR's UI understanding is insufficient for custom-styled buttons.

Frequency: ~25% of ViBR test cases; ~5% of src_LLM

3. Early Exit / Incomplete Workflows

Affected Apps: HomeMedKit (srv), AntennaPod (bad quality with src_LLM)

Root Cause: Models complete 60-70% of steps then fail. Usually occurs after form submission or state change.

Frequency: ~15% of src_LLM test cases; ~20% of ViBR

4. Scrolling & List Navigation Failure

Affected Apps: LuxAlarm (ringtone), AdAway (search results)

Root Cause: Models cannot determine if more items exist below the fold. Affects both frameworks but more severe in ViBR.

Frequency: ~20% of test cases

5. Gesture Recognition (Drag, Swipe)

Affected Apps: Jigsaw (drag puzzle pieces)

Root Cause: Neither implementation has reliable gesture instruction support. This is a model limitation, not framework-specific.

Frequency: ~5% of test cases (but 100% failure when encountered)

For GIFdroid Improvements (src_LLM Focus)

1. Enhance Gesture Recognition (Priority: High)

Jigsaw's 0-2/4 success rate highlights drag-and-drop limitations. Solutions:

  • Implement computer vision for trajectory prediction
  • Add explicit drag-and-drop action primitives
  • Training data augmentation for gesture interactions
2. Improve Scrolling Logic (Priority: High)

Multiple apps fail on scrolling (LuxAlarm, AdAway). Solutions:

  • Visual indicators for "more items available"
  • Bounding box detection for scrollable regions
  • Scroll-until-target strategy instead of single scrolls
3. State Management & Context (Priority: Medium)

Early exits and workflow interruptions suggest context loss. Improvements:

  • Maintain explicit action history (not just visual memory)
  • Detect and confirm state transitions
  • Add rollback capability for failed state changes
4. Input Quality Optimization (Priority: Low)

Bad quality input shows 15-20% performance hit. Improvements:

  • Image stabilization and preprocessing for camera input
  • Reduced reliance on handheld video for critical workflows
  • Hybrid approach: programmatic input when available
