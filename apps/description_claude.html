Executive Summary

Key findings from the comparative evaluation

🏆 Clear Winner

Gemini 2.5-pro outperforms ViBR across 7 out of 8 tested apps (87.5% win rate vs 12.5%).

Achieves 50-80% step accuracy vs ViBR's 0-30%.

⚠️ ViBR's Challenge

ViBR frequently gets stuck due to GroundingDINO region detection failures and rigid state consistency checking.

30% of failures are FAB detection issues.

✅ Gemini's Strength

Simpler architecture (single LLM) beats complex multi-stage pipeline.

Better semantic understanding of app conventions and Material Design patterns.

📹 Screen Recording Advantage

Both systems perform better on screenrec (Good Quality) than handheld (Bad Quality).

Cleaner video enables better keyframe selection and UI detection.

Bottom Line

Use Gemini 2.5-pro for offline trace generation and bug understanding. It's faster, more accurate, and doesn't require a live device. ViBR needs fixes to FAB detection and gesture support before it's production-ready for live replay.

Failure Mode Analysis

Why each system fails and what to fix

🔴 ViBR Failure Patterns

1. GroundingDINO Cannot Detect FABs (30% of failures)

Floating Action Button detection fails consistently. Affects: luxalarm, homemedkit, antennapod.

Fix: Add FAB-specific prompt — "floating action button, FAB, add button, plus button, create button"

Expected gain: +30% accuracy

2. Cannot Handle Drag Gestures (15% of failures)

Drag-and-drop not in action vocabulary. Affects: jigsaw, homemedkit (drag fields).

Fix: Map drag to swipe + offset calculation in ADB layer

Expected gain: +20% accuracy

3. State Consistency Too Strict (20% of failures)

Device screen diverges after a few steps. Consistency check fails → exhaust recovery attempts.

Fix: Relax check, allow minor resolution/layout variations

Expected gain: +25% accuracy

4. Tab Detection Unreliable (15% of failures)

Tab button detection inconsistent. Affects: wifi-analyser, antennapod.

Fix: Add tab-specific prompts to GroundingDINO

Expected gain: +15% accuracy

5. Text Input Unreliable (10% of failures)

Cannot reliably fill text fields. Affects: simplenotes, adaway, luxalarm.

Fix: Improve text field detection — "text input, form field, editable text, search box"

Expected gain: +15% accuracy

🟡 Gemini Limitations

1. Drag-and-Drop Not Supported (15% of failures)

No drag action in Gemini's vocabulary. Affects: jigsaw (0/5 → 2/4 with screenrec).

Workaround: Accept partial completion as better than ViBR's 0/5

2. List Scrolling Limitation (15% of failures)

Cannot detect scrollable regions. Affects: luxalarm (Select Ringtone), simplenotes.

Workaround: SSIM keyframe selection improvement

3. Early Exit Strategy (Conservative but safe)

Chooses to stop rather than risk wrong action. Affects: homemedkit (7/10 then stop).

✅ This is actually a feature, not a bug — better than hanging indefinitely

4. Handheld Video Quality Issues (20% of failures)

Worse on Bad Quality than Good Quality. Example: antennapod 6/10 (Bad Quality) vs 7/7 (Good Quality).

Workaround: Prefer screenrec when available; improve SSIM for motion video

Key Insights

Strategic observations from the test results

1. GroundingDINO is ViBR's Bottleneck

~40% of ViBR failures trace back to GroundingDINO:

  • Cannot detect FABs (luxalarm 0/8, homemedkit 0/10, antennapod 0/10)
  • Cannot reliably detect tabs (wifi-analyser, antennapod)
  • Struggles with custom UI elements (adaway, jigsaw)

Root cause: Model trained on COCO dataset (general objects), not UI elements.

2. Simpler Pipeline Wins

Gemini (1 LLM): 87.5% win rate

ViBR (CLIP → GroundingDINO → GPT-4o): 12.5% win rate

Fewer components = fewer failure points. Each stage in ViBR compounds errors.

3. Gemini Better at App Semantics

Recognizes Material Design patterns natively:

  • Form navigation: homemedkit 7/10 (Gemini) vs 0/10 (ViBR)
  • Tab navigation: wifi-analyser 4/4 (Gemini) vs 3/4 (ViBR)
  • List management: adaway 4/7 (Gemini) vs 1/7 (ViBR)
4. Screen Recording Quality Matters

Good Quality wins over Bad Quality consistently:

  • antennapod: 7/7 (Good Quality) vs 6/10 (Bad Quality)
  • wifi-analyser: 6/8 (Good Quality) vs 4/4 (Bad Quality)
  • Cleaner video = better SSIM keyframe selection
5. "Early Exit" is Better Than "Stuck"

homemedkit: Gemini 7/10 (exits gracefully) vs ViBR 0/10 (indefinitely stuck)

Partial completion with known limits > ambitious failure. Conservative strategy beats hanging.

6. Gesture Support is Unsolved

Both systems fail on drag mechanics (jigsaw: 0/5 and 0/4).

Neither has gesture abstraction beyond tap/scroll/type. Would require custom gesture mapping layer.

7. Device Not Required for Trace Generation

src_llm (Gemini) wins without live device:

  • No ADB communication delays
  • No live state divergence
  • Batch processing, parallelizable
  • Better for offline analysis and documentation

Recommendations

Actionable improvements for each system

✅ For Immediate ViBR Improvement

1. Add FAB-Specific Detection to GroundingDINO Prompt

Include: "floating action button, FAB, add button, plus button, create button, circular button"

Expected Gain: +30% on luxalarm, homemedkit, antennapod (fixes 3 major failures)

2. Improve Text Field Detection

Enhance prompt: "text input, text field, input box, form field, editable text, search box"

Expected Gain: +15% on simplenotes, adaway, homemedkit

3. Add Gesture Abstraction Layer

Map drag-and-drop to swipe + offset calculation. Support pinch, multi-finger gestures via ADB.

Expected Gain: +20% on jigsaw and 3D apps

4. Relax State Consistency Check

Allow minor resolution/layout variations. Use semantic equivalence instead of pixel comparison.

Expected Gain: +25% on handheld videos

5. Use Gemini 2.5-pro Instead of GPT-4o-mini

ViBR with Gemini: 3/10 vs GPT-4o: 0/10 (homemedkit Bad Quality). Consider API cost trade-off.

Expected Gain: +15% across all apps

🎯 To Maximize src_llm Results

1. Prefer Screen Recording Over Handheld

antennapod: 7/7 (Good Quality) vs 6/10 (Bad Quality). Cleaner = better results.

2. Accept Early Exit as Valid Completion

Don't penalize conservative bailout (6/10 is better than 0/10). Focus on completed steps.

3. Use for Trace Generation, Not Live Replay

Gemini excels at understanding action sequences. Use for bug documentation, test generation, trace analysis.

4. Combine with GroundingDINO for Hybrid Approach

Use Gemini for high-level action sequences + GroundingDINO for FAB/custom element detection.

Expected: Better than either alone

Conclusion

Final verdict and strategic direction

🏆 Gemini 2.5-pro Wins

87.5% success rate across diverse app types. Excels at:

  • Form navigation and semantic UI understanding
  • Conservative but correct action selection
  • Graceful handling of uncertainty (early exit)
  • Offline processing (no device required)

⚠️ ViBR Needs Work

12.5% win rate limited by GroundingDINO. Main bottlenecks:

  • FAB detection failure (30% of failures)
  • Rigid state consistency checking (20% of failures)
  • Limited gesture support (20% of failures)
  • Tab detection unreliability (15% of failures)

With fixes above, could reach 70% accuracy.

Strategic Recommendation

Use Gemini 2.5-pro for offline analysis and trace generation. If live replay on device is required, fix ViBR's GroundingDINO integration before production deployment.

Best approach: Hybrid system using Gemini for action sequencing + specialized GroundingDINO for UI element detection.
