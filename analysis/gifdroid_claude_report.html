Equal failure rates — but different failure modes

Both SRV and HHV fail at 9%, but the reasons differ. SRV failures are caused by unmappable UTG paths. HHV failures cascade from low confidence scores collapsing all screens to a single match, leading to degenerate target sequences that can't be traced.

Why low spread matters

GIFdroid uses confidence scores to differentiate which keyframe matches which UI screenshot. When all scores cluster near the same value (low spread), the algorithm cannot tell screens apart — all keyframes get assigned the same best match, collapsing multi-step interactions into single-screen traces.

Noise vs. real transitions

HHV keyframe over-detection is caused by scene changes triggered by hand movement and camera instability — not genuine UI state transitions. These fake keyframes flood Step 2 with invalid candidates, inflating runtime and degrading mapping accuracy.

What lower LCS means

LCS (Longest Common Subsequence) measures how many GUI states in the detected trace align with the actual UI graph. An LCS of 1 means GIFdroid found only 1 matching state — it essentially produces a minimal stub trace rather than a rich interaction sequence. For test replay, this means coverage is severely reduced.

GIFdroid Limitations with Handheld Video

Five root-cause limitations identified from this dataset

📉

Low & Uniform Confidence Scores

Motion blur, variable lighting, and perspective distortion from handheld recording makes all frames appear equally similar to all screenshot artifacts. The GUI matcher cannot discriminate between distinct screens.

Critical
🔑

Keyframe Over-Detection

The scene-change detector fires on camera/hand movement, not just UI transitions. Results in 5–18× more keyframes than SRV for the same session, flooding the pipeline with false positives.

Critical
🗺

Degenerate Single-Screen Mapping

Low score spread causes all keyframes to map to the same best-match screen. The resulting sequence (e.g., [7,7,7,7,7,7]) cannot be traced through the UTG, leading to pipeline failure or trivial traces.

Critical
⏱

No Early-Exit for Degenerate Cases

When all frames map to 1 screen, GIFdroid still runs exhaustive frame × artifact comparisons. AntennaPod utg03 took 7.6 hours with no meaningful output. No timeout or degenerate-state detection exists.

High Impact
🎨

No HHV-Specific Preprocessing

GIFdroid was designed for clean ADB screen recordings. No video stabilization, motion deblur, color normalization, or perspective correction is applied before feature extraction. All HHV degradation flows from this single design assumption.

High Impact
🔗

Reduced Trace Coverage

Even when HHV runs succeed, they produce traces with lower LCS, fewer unique screens, and fewer actions. The replay traces are not equivalent to SRV traces — they cover a smaller subset of the tested interaction.

Medium
