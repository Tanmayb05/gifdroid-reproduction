Key Reliability Gaps

1) OpenAI model override is not honored

OpenAI calls are hardcoded to gpt-4o in openai_api.py, even when run config sets another llm_model (for example gpt-4o-mini).

2) Handheld replay is state-fragile

The loop allows only max_attempts = 3 for alignment and frequently logs same_state: "no" followed by skipped actions in failed handheld runs.

3) UI XML dump dependency is brittle

ADB/UIAutomator XML dump failures still occur in practice and terminate runs with RuntimeError.

4) LLM JSON formatting can hard-fail runs

When providers return prose plus JSON (or malformed output), extract_json(...) can raise JSONDecodeError and stop execution.

5) Provider errors propagate as fatal

Gemini model/endpoint mismatches (observed HTTP 404) abort the run; there is no automatic fallback to another provider/model.

Design & Maintainability Limits

6) Config/runtime mismatch

output.overwrite is validated in config but not used in runtime; outputs always get a new run-XXX directory.

7) Source type inference is path-heuristic

Source is inferred from filename/path tokens (hhv, srv, handheld, screenrec). Non-standard naming can break classification.

8) Metadata schema drift

Historical metadata is inconsistent (some runs missing llm/llm_model), which complicates aggregate analysis.

9) Action execution is lightly guarded

ADB actions execute directly; unknown actions are ignored with a log line instead of strict failure/recovery policy.

10) Segment index edge cases still surface

At least one real run failed with IndexError: list index out of range while indexing segment frame bounds.

Performance & Coverage

11) Runtime variance is high

Observed durations range from 0.0s to 1244.2s, making throughput planning difficult.

12) Artifact evidence is algorithm-skewed

Current run artifacts are clip-only, so robustness conclusions for ssim remain weak in this workspace.

From 2025 ViBR Paper

Research-Reported Limitations & Threats

This section summarizes explicit caveats reported in docs/research_papers/2025 - ViBR.md (derived from the paper's limitations and validity discussion).

  • Semantic mismatch failure mode: replay can fail when recorded GUI state has no clear semantic correspondence to current device state.
  • Masked-input blind spot: PIN/password-style obfuscation prevents reliable value recovery from video frames.
  • Segmentation edge cases: delayed rendering and video ads can introduce false scene boundaries.
  • Evaluation-size constraint: bug replay evaluation was reduced to 38 recordings after filtering, limiting breadth.
  • Model dependency risk: primary validation centers on GPT-4o, so cross-model generalization remains a stated external-validity concern.
  • Action-space ceiling: reported action primitives are limited (tap/scroll/input/end), excluding complex multi-touch gestures.
  • Human-labeling dependence: ground truth relies on expert manual annotation, introducing potential internal-validity bias despite cross-checking.
Highest-ROI Fix Order
  1. Honor configured OpenAI llm_model consistently.
  2. Harden JSON extraction + provider re-ask on malformed responses.
  3. Add stronger pre-segment state reset/checkpointing.
  4. Improve ADB/UI dump recovery and app-focus health checks.
  5. Implement or remove output.overwrite to match user expectation.
  6. Add schema versioning and richer per-step telemetry for diagnostics.
