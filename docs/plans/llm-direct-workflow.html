GIFdroid — LLM-Direct Video Automation

Active feedback loop: LLM watches video directly and drives live device interaction

No keyframe extraction · Raw video → LLM → Device

Old Workflow (Passive Trace)

  • Extract frames at fixed FPS
  • SSIM keyframe selection step
  • Single LLM call, one-shot
  • Outputs static JSON trace only
  • No live device interaction
  • No feedback loop

New Workflow (Active Agent)

  • Raw .mp4 uploaded directly to LLM
  • No frame extraction or SSIM needed
  • Multi-turn stateful conversation
  • LLM decides each action in real time
  • uiautomator2 executes on live device
  • Screenshot feedback closes the loop

Step-by-Step Breakdown

1
Setup — ADB connects to device, APK is installed and launched. Device serial + package name extracted.
2
Video Upload — Raw .mp4 uploaded to LLM (Gemini Files API or Claude). No SSIM, no frame sampling.
3
Initial Understanding — LLM describes the task goal and intended step sequence from the video. Stored as system context.
4
State Capture — Screenshot + accessibility tree dump via uiautomator2 after every action.
5
LLM Decision — Multi-turn call with video context + history + current screenshot. Returns continue flag + next action.
6
Action Execution — uiautomator2 executes tap, scroll, type, back, etc. on live device.
7
History Update — New screenshot appended; sliding window keeps last N turns; older turns compressed to text.
8
Session End — continue: false or max_steps reached. Session trace JSON written with all actions + screenshots.

Context Management Strategy

A
Turn 1 — Full video + task prompt. LLM produces initial understanding. Video stays as a fixed anchor in system context.
B
Turns 2–N — Only the last N screenshots (sliding window, default N=5) are sent. Earlier screenshots are replaced with text summaries.
C
Compression — LLM is asked to summarize completed steps every K turns to prevent context overflow. Summary injected as a system message.
D
Fallback — Accessibility tree (XML hierarchy) sent alongside screenshot when coordinate resolution is ambiguous. Resource-ids preferred over raw x,y.

Key Risks & Mitigations

HIGH LLM hallucinates wrong coordinates → fall back to resource-id from accessibility tree
HIGH Context overflow from screenshots → sliding window + turn compression
MED uiautomator2 server crash mid-session → auto-reconnect + session checkpoint
MED Gemini API rate limits → inter-step delay + exponential backoff retry
MED App crash during automation → detect via activity monitor, log and stop
LOW max_steps reached before task completes → log clearly, allow manual continuation
