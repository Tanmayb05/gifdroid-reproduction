What is this?

AdbGPT automatically replays Android crash bugs using only prompt engineering — no training data, no hard-coded patterns. It feeds a natural-language bug report into ChatGPT to extract structured steps, then uses ChatGPT again to navigate the live app GUI step-by-step until the crash is triggered.

What goes in

  • Bug report — natural language S2Rs (Steps to Reproduce) written by a developer/user. Often informal, inconsistent, or incomplete.
  • APK file — the Android app binary to run on the emulator.

Example raw bug report text

1. Open the app 2. Go to Settings 3. Tap "Notifications" 4. Toggle "Enable alerts" on → App crashes immediately
S2Rs often have missing steps (e.g., "you need to be logged in first"), vague values ("enter a number"), or words that don't match on-screen labels.

Why LLM beats pattern-matching here

  • Diversified words — LLM understands synonyms
  • Dependent context — LLM reasons holistically
  • Inconsistent formats — LLM tolerates informal language
Accuracy: 90.4% step accuracy vs 51.1% (ReCDroid) and 55.1% (MaCa). Runs in ~2 seconds.

P2
Phase 2 — Guided Replay
LLM maps each step to the live app GUI, one at a time
▶

Loop: for each S2R entity…

  • 1. Capture GUI state — read the current screen's view hierarchy (XML) from the Android device via ADB.
  • 2. Encode to HTML — depth-first traversal converts XML widgets to simplified HTML tags:
    <button id="login_btn">Sign In</button> <input id="user_field" hint="Username"> <p>Forgot password?</p>
  • 3. Prompt LLM — send HTML encoding + 3 few-shot CoT examples + the current S2R entity.
  • 4. LLM picks the target widget — outputs which element to interact with and how.
  • 5. Execute via ADB — action sent to emulator using Android Debug Bridge.

Why HTML encoding?

Screenshots are not used — the view hierarchy (resource-id, text, content-desc) is converted to structured HTML text. This is lightweight and gives the LLM the semantic structure it needs without vision.

Example LLM reasoning (Chain-of-Thought)

S2R: Tap[Notifications] GUI has: <button id="notif">Notifications</button> → "The word 'Notifications' matches the button label exactly. Action: Tap the element with id='notif'."
If an S2R mentions a missing step (e.g., must dismiss a dialog first), the LLM identifies the intermediate action from the GUI state.
↓ ADB command executed on device

Tools used

  • Genymotion — x86-64 Android emulator (macOS)
  • Android Debug Bridge (ADB) — controls the emulator
  • UI Automator2 — issues UI interactions programmatically

Action types

Tap[Component] → adb shell input tap x y Scroll[Direction] → adb shell input swipe … Input[Component][Val] → adb shell input text "val" Double-tap[Component] → two rapid taps Long-tap[Component] → adb shell input swipe x y x y 1000
After each action, control returns to Phase 2 to check the new GUI state before executing the next S2R step.
↓ app state update
OR
Oracle Check
Did the app crash as expected?
▶

Success condition

The app crashes with the expected crash behaviour described in the bug report.

Failure modes

  • No crash → continue to the next S2R entity
  • Timeout (10 min) → stop, mark as not reproduced

What AdbGPT does NOT detect

Only crash bugs are in scope. Non-crash functional bugs (wrong output, visual glitch) are not detected — this is a noted limitation and motivation for follow-up work like ReBL.

What happens when you remove each component?

Full AdbGPT (few-shot + CoT) 81.3%
w/o Chain-of-Thought 62.5%
w/o Few-shot examples 58.3%

Both few-shot and CoT are critical. CoT provides the larger benefit for guided replay — it lets the LLM reason about why a widget matches, not just pattern-match on the label.

Limitations

Input values

Cannot generate specific inputs (e.g., a valid URL). Uses generic placeholders — causes failures for fields with format constraints.

Crash-only

Oracle only detects app crashes. Non-crash functional bugs (wrong output, UI glitches) are out of scope.

Multi-lingual

Fails when GUI language differs from bug report language (e.g., French app, English S2Rs).

Non-determinism

LLM output varies — results are averaged over 3 runs. API cost and availability are practical constraints.
